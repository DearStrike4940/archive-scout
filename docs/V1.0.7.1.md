# Archive Scout 1.0.7.1

Patch baseline: the uploaded v1.0.7 repository, GitHub archive commit
`405f5eebdb4fbb165c9a5c718549848065cc80a6`. Schema remains 8.

## Reports workspace

- Reports is visible in Simple and Advanced mode between Media and Archive analysis.
- Every existing standard scan/index/error/media/analysis report and its fields remain individually selectable. Scrollbars keep the complete matrix reachable.
- Added report presets, sorting, maximum matched captures, per-match snippet count/length and link limits. Zero means all available. Match selection is shared by ranked matches, URL lists, keyword totals and interesting links.
- Disabling an output or field no longer wipes historical match JSON or review rows. Full scan details are retained by default. Optional lean enrichment affects future scans; it never removes old evidence.
- Existing detail already removed by v1.0.7 cannot be recovered from a checkbox. Run a local rescan to recreate it from saved captures.

## Acquisition, content and Hitlist

- Retains 10 replay workers and 0.125-second shared request-start spacing: up to eight request starts per second, not a promise of eight completed captures per second. Network latency, rate limits, size and disk speed still affect completions.
- Full runs finish network acquisition before local scanning. Download-only stays free of documents, matches, scan jobs and payload hashing.
- New textual captures use URL-derived `.txt` filenames; bytes and markup remain intact. Existing saved filenames remain valid. Portable filename collisions get a unique destination rather than adopting another capture's file.
- Text/media decisions inspect content, not just filename suffixes. PNG/JPEG/GIF/TIFF/ICO, common audio/video/archive containers and PDFs cannot become text solely because of a bad MIME header. SVG stays searchable. Arbitrary HTML pages cannot be saved as downloaded images/videos.
- Unicode/legacy decoding and literal matching retain full-source coverage. The successful decode is reused; repeated literal occurrences are counted in bounded batches with cross-boundary overlap.
- Hitlist reads files through the capture manifest, honors saved charset hints, excludes binary bodies from text coverage and reports missing/unreadable content as unavailable. Pausing inside a batch no longer skips unsaved results on Resume.
- Full-run rate-limit pauses no longer call an undefined completion-buffer function. Download-only flushes saved completions before a deferred pause. A failing local scanner is not retried forever within the same operation.
- Worker-start failures restore controls. Startup emits an early database-opening message. Newer unsupported databases are refused rather than treated as legacy projects, and a failed migration backup prevents schema changes.

## CDX and connections

- CDX page work is bounded by active workers, including completed response bodies waiting for SQLite; a rolling 1,000-page scheduling window no longer means up to 1,000 retained response bodies.
- Malformed JSON rows are rejected as an incomplete page instead of being silently discarded. Valid JSON/text format detection and recovery remain. This release does not accept truncated CDX pages to appear faster.
- A page-count timeout returns to the durable fallback logic immediately instead of multiplying the full wait five times. Known numbered-page checkpoints and failed-page retry queues are preserved.
- Copied CDX request links resolve to their original target; wholly encoded URLs are decoded at the input boundary. Real escaped path/query content is preserved. Common CDX syntax is readable in the actual request URL, while reserved characters inside parameter values stay safely quoted.
- Request preview uses the configured endpoint and strategy, shows decoded parameters separately, and copies the exact request URL. Never decode an entire finished request URL by hand: nested ampersands/pluses can change which request is sent.
- HTTPX/urllib3/curl use consistent environment/proxy policy. A backend initialization failure no longer prevents remaining automatic backends from starting. An explicitly selected backend does not initialize unrelated backends.
- Resumed replay requires a matching Content-Range offset and total length. Invalid ranges/416 get one clean restart; short/mismatched bodies are not accepted. Identity encoding keeps offsets meaningful. Valid partial bytes survive read failures.
- urllib3 closes rejected/cancelled bodies without draining an unbounded stalled response; successful responses retain connection reuse. TLS verification remains enabled.

Encoding regression tests cover copied and double-encoded full URLs, escaped paths, nested queries, repeated filters and resume keys containing reserved characters. These are reproducible fixes, not a diagnosis of every reported connection failure.

Run the existing CI/build matrix and packaged-app smoke tests before publishing the tag.

## Upgrade

Close Archive Scout, then merge the patch's `repository-files/` contents into the matching v1.0.7 source checkout, preserving paths. Rebuild the application from source; editing an installed application bundle is not an upgrade. Existing project data does not need to be deleted or re-indexed. Resume unfinished acquisition using the original operation/settings. Download-only projects can continue by selecting Download-only again; their saved queue and capture paths are reused.

The patch does not include a new Discord runtime or change the existing CLI contract. GUI and automation share the corrected engine. No GitHub release or tag is published by applying these source files.
